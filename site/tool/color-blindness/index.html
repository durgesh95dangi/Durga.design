What it does

About the Color Blindness Simulator.

A color blindness simulator approximates how a color or interface looks under common color vision deficiencies such as protanopia, deuteranopia, and tritanopia.

About 8% of men have some form of red-green deficiency. Charts, status dots, and error states that rely on hue alone fail that group. This preview uses standard CVD transforms in the browser so you can catch those failures in a mockup.

How to use

Three steps.

Set

Pick a color, or upload a screenshot or mockup from your machine.

Read

Switch between common CVD types and compare against the original.

Copy

Adjust the design until meaning still holds without relying on hue alone.

When to use it

Where it helps.

Use it on dashboards, maps, form validation, and any Fintech state that is only red versus green. Pair it with the contrast checker so type still reads after the hue shift.

FAQ

FAQ.

Which types of color vision deficiency can I preview?

The simulator covers common types including protanopia, deuteranopia, and tritanopia, so you can spot palettes that collapse for red-green or blue-yellow deficiencies.

Is my screenshot uploaded?

No. The image is read locally in your browser and the CVD transform is applied on the device. Nothing is sent to a server.

Is a simulator the same as talking to people with CVD?

No. It is a fast check, not a substitute for research. Use it to catch obvious hue-only encodings before usability testing.

How should I fix a palette that fails the preview?

Add a second cue: icon, pattern, position, or label. Do not rely on color alone for success, error, or warning.
